# wechat-single-file-report

## When to use
- 用户希望抓取“某个主题在微信公众号里的信息”，并要求可直接转发的结构化产物。
- 用户明确要两个文件：一个 Excel 清单 + 一个 Word 速读总结。
- 用户需要“按价值排序”，且价值口径以阅读量/互动量为主。
- 用户希望后续其他 Agent 安装后也能复用同一套流程。

## Steps
1. 先收集或确认 4 个参数（缺失时给默认值并明确告知）：
   - 主题/问题（自然语言）
   - 目标篇数（默认 50，上限建议 80；若用户要“全部”，则不过滤篇数）
   - 最低阅读量阈值（默认 500）
   - 时间范围（默认近20天，也支持近N天）

2. 自动生成关键词（5-10个）：
   - 保留用户原始主题词作为 `SEED_KEYWORD`；
   - 扩展同义词/上下游词作为 `expand_keywords`；
   - 去重后执行检索。

3. 抓取与标准化：
   - 抓取字段：`发布人/发布时间/发布标题/发布链接`；
   - 解析可得的 `阅读量/互动量`（互动量可来自点赞/在看/评论/转发/热度等公开字段）；
   - 若阅读量或互动量不可得，标记为 `--`（不得伪造）。

4. 筛选与排序：
   - 先按时间范围过滤；
   - 再按主题相关度去重；
   - 价值排序优先级：`阅读量 desc -> 互动量 desc -> 发布时间 desc`；
   - 若阅读量/互动量缺失，则自动降级为 `发布时间 desc`。

5. 产出两个文件：
   - Excel：`微信文章价值清单_<YYYYMMDD>.xlsx`
     - 字段固定：`发布人 | 发布时间 | 发布标题 | 发布链接 | 阅读量 | 互动量`
   - Word：`微信文章速读总结_<YYYYMMDD>.docx`
     - 固定结构：
       1) `主题`
       2) `核心观点（标注文章来源）`
       3) `200字内总结（基于已抓取内容）`
       4) `口径说明（阅读量/互动量缺失时如何处理）`

6. 推荐执行脚本：
   - `python wechat-single-file-report/wechat_dual_report.py --theme "你的主题" --max-urls 50 --read-threshold 500 --lookback-days 20`

7. 二次校验后交付：
   - Excel 字段、排序、时间过滤正确；
   - Word 包含来源标注与200字内总结；
   - 输出成功数/失败数/最终样本数/文件路径。

## Pitfalls
- 不要跳过参数确认；主题模糊会直接导致召回偏移。
- 自动扩词时必须保留用户原词，避免“泛词高召回、低相关”。
- 微信反爬常导致阅读量/互动量不可得：必须标记 `--` 并写入口径说明，不得写 0 冒充真实数据。
- 用户要求“全部文章”时，不要默认截断到 50。
- Word 总结必须标注文章来源（标题+发布人+日期），不能只给抽象结论。
- 200字总结要可直接给业务方看：先结论、后判断，避免口号化。

## Verification
- 已记录用户参数：主题/篇数/阅读量阈值/时间范围。
- Excel 文件名符合：`微信文章价值清单_<YYYYMMDD>.xlsx`。
- Excel 字段严格为：`发布人 | 发布时间 | 发布标题 | 发布链接 | 阅读量 | 互动量`。
- 排序规则满足：`阅读量 -> 互动量 -> 发布时间`（或缺失时自动降级）。
- Word 文件名符合：`微信文章速读总结_<YYYYMMDD>.docx`。
- Word 包含：主题、核心观点（含来源）、200字内总结、口径说明。
- 终端日志包含：抓取成功数、失败数、最终样本数、输出文件路径。
